# Phantom Audit — Kiroween 2026 Hackathon Strategy

## 1. Category & Identity

- **Category:** Costume Contest
- **Theme Concept:** Accessibility auditor disguised as an interactive haunted Victorian mansion.
- **Narrative Hook:** Accessibility bugs aren't dry numbers—they're ghosts haunting your website. Clean your code, banish the ghosts, and make each room peaceful.

## 2. Competitive Differentiators

1. **Engaging Metaphor with Zero Fluff:** Translates technical WCAG criteria into tangible, intuitive mansion rooms without losing rule IDs, selectors, or impact levels.
2. **Actionable Remediation over Blame:** Provides plain-language explanations, user impact summaries, and copyable safe fix code snippets.
3. **Verified Before/After Fix Cycle:** Enables live rescans and presents clear comparison diffs (resolved vs unchanged vs new findings).
4. **Uncompromised Self-Accessibility:** Models exemplary accessibility in its own UI (keyboard navigation, high contrast, reduced motion, screen reader live updates).
5. **Privacy-First & Zero Cost:** Runs 100% locally in the browser sandbox. No backend, API keys, or paid infrastructure required.

## 3. Demo Storyboard Milestones (Under 3 Minutes)

- **0:00–0:15:** Problem introduction on deliberately inaccessible sample website.
- **0:15–0:35:** User invokes Phantom Audit on active tab.
- **0:35–1:00:** Reveal haunted mansion with rooms haunted by real detected findings.
- **1:00–1:30:** Inspect finding (Name Chamber: `button-name`), selector, and remediation fix.
- **1:30–1:55:** Fix website code and rescan.
- **1:55–2:15:** Show finding resolved, room cleared, and before/after comparison.
- **2:15–2:40:** Showcase self-accessibility, Kiro steering/specs/hooks, and local report export.
